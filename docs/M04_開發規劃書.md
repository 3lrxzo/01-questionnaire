# 金寶貝健康問卷模組（M04）—— 開發環境建置與架構規劃書

> 本文件給 Claude Code 使用，作為專案起手依據。內容涵蓋：環境安裝、技術棧決策、資料模型、API 規劃、開發階段拆分。

## 一、專案背景（一句話版本）

建置一套**問卷管理系統**，讓兒科部人員在後台自訂問卷（題目、選項、分支條件、適用規則），家長透過網頁在手機上以「一次一題」的方式填答，資料回存至兒童健康紀錄。第一階段須支援 Tier 0～Tier 5 六種分層應用情境作為最低驗收基準，但系統架構不得寫死在這六種情境上。

**核心設計原則：問卷內容（題目/選項/分支）不寫死在程式碼裡，全部由後台資料驅動。**

---

## 二、技術棧決策總覽

| 層 | 技術 | 決策理由 |
|---|---|---|
| 後端 API / 商業邏輯 | **Django + Django REST Framework** | 開發者本身熟悉 Django |
| 資料庫 | **PostgreSQL**（用 `JSONB` 存問卷 schema 彈性欄位） | 關聯式資料 + 半結構化 schema 並存的需求 |
| 後台管理頁面 | **Django Template + HTMX + Alpine.js** | 標準 CRUD 操作，維持低學習成本，不需要 SPA |
| 家長端問卷填答頁 | **Vue 3（CDN 引入，無 build tool，Options API）** | 分支邏輯需要前端即時反應，避免每答一題就打一次 server |
| 家長端交付形式 | **Responsive Web App + `manifest.json`（PWA-lite）** | 先不上架 App Store/Google Play，降低審核與打包的學習與時程成本；之後有需要再評估 Capacitor 包殼上架 |
| 條件分支邏輯 | 先用 Python function／簡單規則存 DB，**不**一開始上通用 rule engine（如 JSON Logic） | 先求能動、可展示，避免過早過度工程化 |

**重要邊界**：Vue 3 **只**用在「問卷填答頁」這一頁，不要把整個後台或其他頁面也重寫成 Vue SPA。其餘頁面維持 Django Template + HTMX，不要引入 Vite / Vue Router / Pinia / TypeScript / SFC(`.vue`) 這些工具鏈。

## 三、環境安裝清單

開發者已有 `virtualenvwrapper`，並已建立 `django_venv` 虛擬環境，優先沿用該環境，不需另外新建。

### 3.1 macOS（MacBook Air M3 / Mac Studio）

```bash
# PostgreSQL
brew install postgresql@16
brew services start postgresql@16
createdb m04_questionnaire

# 啟用既有虛擬環境
workon django_venv

# Python 套件
pip install django djangorestframework psycopg2-binary python-dotenv
```

### 3.2 Fedora 41（桌機）

```bash
# PostgreSQL
sudo dnf install postgresql postgresql-server postgresql-devel
sudo postgresql-setup --initdb
sudo systemctl enable --now postgresql
sudo -u postgres createuser --interactive   # 建立自己的 db user
sudo -u postgres createdb m04_questionnaire

# 啟用既有虛擬環境
workon django_venv

# Python 套件（psycopg2 在 Fedora 需要 postgresql-devel 才能編譯）
pip install django djangorestframework psycopg2-binary python-dotenv
```

### 3.3 Windows PC

```powershell
# Git（若尚未安裝）
winget install --id Git.Git -e --source winget

# PostgreSQL
winget install --id PostgreSQL.PostgreSQL -e

# 安裝完成後開啟 pgAdmin 或用 psql 建立資料庫
createdb -U postgres m04_questionnaire

# Python（若尚未安裝）
winget install --id Python.Python.3.12 -e

# 虛擬環境（Windows 沒有 virtualenvwrapper 慣用的 workon，建議用標準 venv）
python -m venv django_venv
.\django_venv\Scripts\activate

pip install django djangorestframework psycopg2-binary python-dotenv
```

> 注意：`virtualenvwrapper` 在 Windows 上設定較麻煩，且與 macOS/Fedora 那邊的環境本來就是分開管理，不需要共用同一個虛擬環境。三台機器各自維護自己的 venv 即可，靠 `requirements.txt` 同步套件版本。

### 3.4 前端相關

**不需要安裝 Node.js / npm。** Vue 3 與 Alpine.js 皆透過 CDN `<script>` 標籤引入，HTMX 同理。這是刻意的決定，避免引入 Node 生態系的建構工具鏈。

```html
<!-- 在對應的 Django template 裡引入 -->
<script src="https://unpkg.com/vue@3/dist/vue.global.js"></script>
<script src="https://unpkg.com/htmx.org@1.9.10"></script>
<script src="//unpkg.com/alpinejs" defer></script>
```

## 五、資料模型設計（核心）

以下為第一階段建議的 model 骨架，欄位可依實作細節微調：

```python
# questionnaires/models.py

class Questionnaire(models.Model):
    """問卷主檔 —— 不含題目，只存名稱/分類/Tier/狀態等中繼資料"""
    name = models.CharField(max_length=200)
    description = models.TextField(blank=True)
    category = models.CharField(max_length=100)   # 健康管理/日常追蹤/疾病/心理/功能...
    tier = models.CharField(max_length=20)         # Tier 0 ~ Tier 5，未來可擴充
    created_at = models.DateTimeField(auto_now_add=True)


class QuestionnaireVersion(models.Model):
    """版本管理 —— 已發布版本不可覆寫，改版建新版本"""
    STATUS_CHOICES = [("draft", "草稿"), ("published", "已發布"), ("retired", "已停用")]
    questionnaire = models.ForeignKey(Questionnaire, related_name="versions", on_delete=models.CASCADE)
    version_number = models.PositiveIntegerField()
    status = models.CharField(max_length=20, choices=STATUS_CHOICES, default="draft")
    published_at = models.DateTimeField(null=True, blank=True)

    class Meta:
        unique_together = ("questionnaire", "version_number")


class Section(models.Model):
    """題組 —— 一組相關題目，可作為條件式追問的觸發單位"""
    version = models.ForeignKey(QuestionnaireVersion, related_name="sections", on_delete=models.CASCADE)
    title = models.CharField(max_length=200)
    order = models.PositiveIntegerField()


class Question(models.Model):
    QUESTION_TYPES = [
        ("single", "單選"), ("multi", "複選"), ("number", "數值"),
        ("text", "簡短文字"), ("scale", "量表"), ("datetime", "日期/時間"),
    ]
    section = models.ForeignKey(Section, related_name="questions", on_delete=models.CASCADE)
    prompt = models.CharField(max_length=500)
    question_type = models.CharField(max_length=20, choices=QUESTION_TYPES)
    required = models.BooleanField(default=True)
    order = models.PositiveIntegerField()


class Option(models.Model):
    """選項（單選/複選/量表用）"""
    question = models.ForeignKey(Question, related_name="options", on_delete=models.CASCADE)
    label = models.CharField(max_length=200)
    value = models.CharField(max_length=100)
    order = models.PositiveIntegerField()


class BranchRule(models.Model):
    """分支條件 —— 先用簡單結構：某題答案觸發某題組顯示/隱藏"""
    trigger_question = models.ForeignKey(Question, related_name="triggers", on_delete=models.CASCADE)
    trigger_value = models.CharField(max_length=100)   # 觸發的答案值
    target_section = models.ForeignKey(Section, related_name="triggered_by", on_delete=models.CASCADE)
    action = models.CharField(max_length=20, choices=[("show", "顯示"), ("hide", "隱藏")])


class EligibilityRule(models.Model):
    """適用規則 —— 年齡/個案條件/追蹤狀態/適用時期"""
    version = models.ForeignKey(QuestionnaireVersion, related_name="eligibility_rules", on_delete=models.CASCADE)
    min_age_months = models.PositiveIntegerField(null=True, blank=True)
    max_age_months = models.PositiveIntegerField(null=True, blank=True)
    condition_json = models.JSONField(default=dict, blank=True)   # 彈性擴充其他條件


class QuestionnaireResponse(models.Model):
    """一次完整填答紀錄"""
    STATUS_CHOICES = [("in_progress", "未完成"), ("completed", "已完成")]
    child = models.ForeignKey("children.Child", related_name="questionnaire_responses", on_delete=models.CASCADE)
    version = models.ForeignKey(QuestionnaireVersion, related_name="responses", on_delete=models.PROTECT)
    started_at = models.DateTimeField(auto_now_add=True)
    completed_at = models.DateTimeField(null=True, blank=True)
    status = models.CharField(max_length=20, choices=STATUS_CHOICES, default="in_progress")
    source = models.CharField(max_length=50, default="parent")   # 資料來源：家長/照顧者填報


class Answer(models.Model):
    """單題填答內容"""
    response = models.ForeignKey(QuestionnaireResponse, related_name="answers", on_delete=models.CASCADE)
    question = models.ForeignKey(Question, on_delete=models.PROTECT)
    value = models.JSONField()   # 依題型彈性存值（單一值/陣列/數值/文字）
```

**設計重點提醒給 Claude Code**：
- `QuestionnaireResponse` 用 `PROTECT` 而非 `CASCADE` 綁定 `version`，確保版本被停用/改版時，舊填答紀錄不會被牽連刪除或遺失版本關聯（對應文件第九節「歷史資料保留」要求）。
- `BranchRule` 先用最簡單的「單一觸發題目 + 單一觸發值」結構，若後續需要多條件 AND/OR 組合，再評估是否要升級成獨立的 rule engine，不要一開始就做通用化。

## 六、API 端點規劃（給 Vue 填答頁用）

| Method | Endpoint | 用途 |
|---|---|---|
| GET | `/api/questionnaires/{version_id}/schema/` | 回傳完整問卷 schema（題組/題目/選項/分支規則），Vue 載入時一次抓取 |
| POST | `/api/responses/` | 建立新的填答紀錄（開始填答） |
| PATCH | `/api/responses/{id}/autosave/` | 暫存單題或單題組答案（對應「暫存續填」） |
| POST | `/api/responses/{id}/complete/` | 完成送出 |
| GET | `/api/responses/{id}/` | 續填時取回已填內容 |

## 七、開發階段拆分

### Phase 1（優先，10 月前目標）
- Django model + admin（先用 Django Admin 客製化做後台，不用急著刻 HTMX 頁面）
- 一種 Tier（例如 Tier 1 日常檢核）跑通完整流程：建立問卷 → 發布 → Vue 頁面呈現 → 條件分支（發燒範例）→ 送出 → 存入 `QuestionnaireResponse`
- 版本管理走最陽春的實作：新版本就是新的 `QuestionnaireVersion` row，先不做覆雜的 diff/比較功能
- 「未完成/未記錄」狀態先用 `QuestionnaireResponse.status` 簡單判斷

### Phase 2（有餘裕後再做）
- 後台改成 HTMX 頁面（脫離陽春 Django Admin）
- Tier 0～Tier 5 全部題型補齊
- 適用規則（`EligibilityRule`）的判斷邏輯完整化
- PWA `manifest.json` + service worker，讓家長「加入主畫面」
- 如需推播提醒，評估 Capacitor 包殼上架

## 八、版本控制與跨裝置開發（Git / GitHub）

開發環境會在 **Windows PC** 跟 **MacBook** 之間切換，因此版本控制策略要特別處理「跨機器環境差異」跟「不要把機敏/機器相依的檔案 commit 進去」這兩件事。

### 8.1 Repo 初始化

```bash
git init
git branch -M main
git remote add origin https://github.com/<你的帳號>/m04_questionnaire.git
git add .
git commit -m "Initial commit: project skeleton"
git push -u origin main
```

建議請 Claude Code 在專案初始化時就順手建立 repo 並完成第一次 commit，不要等到功能做完才補。

### 8.2 `.gitignore`（務必在第一次 commit 前就設好）

```gitignore
# Python
__pycache__/
*.pyc
django_venv/
venv/
.venv/

# Django
*.sqlite3
staticfiles/
media/

# 環境變數（DB 帳密等機敏資訊，每台機器各自維護自己的 .env，不進版控）
.env

# IDE
.vscode/
.idea/

# OS
.DS_Store
Thumbs.db
```

**關鍵提醒**：`.env`（存 DB 帳號密碼）**絕對不要 commit**，因為 Windows 跟 Mac 上的 PostgreSQL 帳密、連線設定大概率不同。改用 `.env.example` 這個「範本檔」進版控，讓每台機器照著範本各自建立自己的 `.env`：

```bash
# .env.example（這個要 commit）
DATABASE_NAME=m04_questionnaire
DATABASE_USER=your_db_user
DATABASE_PASSWORD=your_db_password
DATABASE_HOST=localhost
DATABASE_PORT=5432
```

### 8.3 跨機器同步套件版本

因為 Windows 跟 macOS 的虛擬環境是各自獨立建立的（見 3.1／3.3），套件版本要靠 `requirements.txt` 對齊，而不是共用同一個 venv：

```bash
# 在其中一台裝完套件後
pip freeze > requirements.txt
git add requirements.txt && git commit -m "Update dependencies"

# 換到另一台機器時
git pull
pip install -r requirements.txt
```

每次切換機器開始開發前，養成習慣先 `git pull` + `pip install -r requirements.txt`，避免套件版本落差導致 migration 或程式行為不一致。

### 8.4 Migration 檔案要進版控

Django 的 `migrations/` 資料夾（`*.py` 檔）**要**commit，不要放進 `.gitignore`——這是跨機器同步資料庫結構的方式。切換機器後記得跑：

```bash
git pull
python manage.py migrate
```

### 8.5 簡單分支策略

專案規模跟時程（10 月前要有成果）不需要複雜的 branching model，建議：
- `main`：隨時可展示的穩定版本
- 開發新功能時開 `feature/xxx` 分支，完成後 merge 回 `main`
- 不需要 `develop` 分支、不需要 GitFlow 這種較重的流程

### 8.6 換機器前的收尾習慣

每次要換去另一台機器前：
```bash
git add .
git commit -m "WIP: <說明>"
git push
```
即使功能沒做完也先 commit + push（用 `WIP:` 前綴標記），確保另一台機器可以直接 `git pull` 接續，不會有「東西留在某台機器上忘記帶」的問題。
